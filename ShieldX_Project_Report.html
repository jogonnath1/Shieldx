ShieldX — Crime Reporting Management System

Project Report

Abstract

ShieldX is a mobile application developed to revolutionize crime reporting and management within the Sylhet Metropolitan Police (SMP) jurisdiction. Traditional manual reporting systems are often slow and inefficient. ShieldX addresses this by providing citizens with a secure, real-time platform to submit complaints, upload evidence, and track the status of their reports. For administrators and police officers, it offers a comprehensive dashboard to manage, assign, and respond to these complaints effectively. Built using Flutter for the frontend and Supabase for a robust, real-time backend, ShieldX ensures fast response times, especially through its one-tap SOS emergency feature with live GPS tracking. This project demonstrates the successful integration of modern mobile app technologies to improve public safety and police transparency.

Index Terms — Crime Reporting; Flutter; Supabase; Real-time; Emergency Tracking; Mobile Application.

Chapter 1: Introduction

In today's fast-paced world, public safety relies heavily on the efficiency of crime reporting and the responsiveness of law enforcement. The Sylhet Metropolitan Police (SMP) requires an effective system to manage citizen complaints, track emergencies, and visualize crime data in real-time. ShieldX is developed to bridge the gap between citizens and the police department by offering a dedicated mobile application for both parties.

This report is structured to guide the reader through the research, design, and implementation of ShieldX systematically. Chapter 2 describes the problem and our objectives. Chapter 3 outlines the functional and non-functional requirements, including UML design diagrams. Chapter 4 details the methodology, architecture, and accomplishments during development. Chapter 2: Problem Description

2.1 Problem Statement

The traditional methods of reporting crimes—such as making phone calls or physically visiting a police station to file a First Information Report (FIR)—are often time-consuming and lack transparency for the citizen. Furthermore, law enforcement agencies struggle with paper-based records or fragmented digital systems that do not provide real-time analytical dashboards or live tracking of emergencies. The goal of this project is to create "ShieldX", a comprehensive mobile-based Crime Reporting Management System that provides real-time communication, automated status tracking, and emergency GPS alerts.

2.2 Goals

  • Develop a multi-platform mobile application using Flutter for citizens and police administrators.
  • Implement secure user authentication including NID validation and OTP verification.
  • Provide a seamless interface for citizens to submit and track crime reports with multimedia evidence.
  • Build a real-time admin dashboard with statistical charts, location heatmaps, and complaint management tools.
  • Implement an SOS emergency feature with live GPS tracking.

2.3 Purposes

The primary purpose of ShieldX is to increase crime reporting rates by making the process accessible and transparent, thereby improving public trust. For the police department, it aims to reduce response times, centralize data management, and provide actionable insights into crime trends across different jurisdictions in Sylhet.

2.4 Methods

The project is built using a modern, layered architecture. The front-end is developed using Flutter (Dart) for cross-platform compatibility. The state management is handled by Riverpod, and navigation is managed by GoRouter. The backend is powered by Supabase, utilizing PostgreSQL for the database, Row Level Security (RLS) for data protection, and Supabase Realtime for instant updates across devices.

2.5 Related Work

While there are national emergency numbers (like 999) and various generic reporting tools, specialized apps dedicated to localized jurisdictions with integrated real-time tracking, evidence uploading, and dedicated admin management panels are limited. ShieldX builds upon the concepts of existing national platforms but offers a much more targeted, feature-rich, and real-time experience specific to the Sylhet Metropolitan Police structure.

Chapter 3: Requirement Specification

3.1 Functional Requirements

  • Authentication: Multi-step registration with email/phone OTP verification and NID validation.
  • Complaint Management (Citizen): Submit complaints with auto-classification, map-based location picking, and photo evidence. Track real-time status (submitted → in progress → investigating → resolved).
  • SOS Emergency: One-tap alert with a 3-second cancellation window and live GPS location tracking.
  • Admin Dashboard: Live statistics (pie/bar charts), monthly trends, and location heatmaps. Filter, sort, assign, and update complaints.
  • User Management (Admin): Verify, block/unblock, promote, and manage field officers.
  • Notifications: Real-time push notifications for status changes.

3.2 Nonfunctional Requirements

  • Security: Strict Row Level Security (RLS) ensuring citizens only access their own data. Admin routes protected via router redirects and database policies.
  • Performance: Real-time data synchronization using Supabase Realtime Postgres Change Events.
  • Reliability: Offline fallback for complaint submission (syncing when reconnected) and a 4-step GPS fallback chain to ensure location accuracy.
  • Maintainability: Layered architecture separating UI, State (Riverpod), and Data (Services), with 0 errors/warnings in static analysis.

Chapter 4: Accomplishment

4.1 Preliminaries

The project began by defining the architecture and selecting the appropriate tech stack. Flutter SDK (≥ 3.0) and Dart SDK (≥ 3.0) were chosen for the UI, while Supabase was configured to act as the Backend-as-a-Service, handling PostgreSQL tables, RPC functions, Storage, and Realtime channels.

4.2 How the Work Was Done

The application was built adhering to a layered architecture: 1. Data Layer (lib/data/services/): Isolated all Supabase API communications. Created distinct services like AuthService, ComplaintService, EmergencyService, and SyncService for offline support. 2. Provider Layer (lib/providers/): Utilized Riverpod StateNotifiers and StreamProviders to manage application state securely and responsively. This layer acts as the single source of truth for the UI. 3. Presentation Layer (lib/presentation/): Developed role-specific interfaces (Admin vs. User) utilizing GoRouter for declarative, redirect-based navigation.

Key design decisions included extracting duplicate logic into shared helpers (e.g., _buildStatusStats()), implementing a robust 4-step GPS fallback chain (Simulation -> Device GPS -> Last Known -> Default Location), and utilizing Supabase Realtime for instant UI updates when admins modify user roles or complaint statuses. Extensive code cleanup was performed, resulting in a strictly formatted, zero-error codebase.

Chapter 5: Results

The successful outcome of this project is the fully functional ShieldX mobile application. - User Interface: A seamless, animated (via flutter_animate), and intuitive UI for both citizens and administrators. - Functional Outcomes: Citizens can successfully authenticate via OTP, submit detailed complaints with media, and trigger an SOS. Administrators have access to a rich dashboard populated with fl_chart visualizations and an interactive flutter_map. - Technical Outcomes: The application achieves real-time data sync without manual polling, enforces strict row-level security for data privacy, and gracefully handles offline scenarios.

Chapter 6: Conclusion

The ShieldX project successfully achieved its original goals of providing a comprehensive, real-time crime reporting and management system. By leveraging Flutter and Supabase, the application delivers a modern user experience with robust backend security and real-time synchronization.

6.1 Restrictions

The application requires active internet connectivity for real-time features (though it supports offline queueing for complaint submissions) and necessitates user permission for GPS location tracking.

6.2 Limitations

Currently, the system is constrained to handling image-based evidence; video uploads are not fully supported due to storage constraints. Additionally, the map bounds and station logic are heavily tailored exclusively to the Sylhet Metropolitan Police (SMP) region.

6.3 Future Work

Future iterations of ShieldX could include: - AI-based automatic classification and prioritization of submitted complaints. - Support for video evidence compression and uploading. - Expansion to support multiple city jurisdictions beyond Sylhet. - Integration with national identity databases for automated, instant NID verification.

Appendix B: User's Guide

For Citizens: 1. Download and open ShieldX. 2. Register using your Email, Phone Number, and NID. 3. Verify your account via the OTP sent to your device. 4. Use the "Submit Complaint" button to report an incident, or press and hold the "SOS" button in case of an emergency.

For Administrators: 1. Log in with admin credentials. 2. Review the live Dashboard for an overview of recent activities and statistics. 3. Navigate to the "Complaints" tab to review pending reports, assign officers, and update statuses to keep citizens informed.
